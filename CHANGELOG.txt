TeamCamel change log
====================

Newest version first.


Version 2.9.2 - 2026-10-23
--------------------------

Fixed
- A session whose turn ended with the Claude app's closing card asking you a
  question, with answer buttons ("Add both warnings" / "Skip them"), showed
  as completed. The app itself counts such a question as waiting on you only
  when Claude marks it as blocking; one that "can wait" stays on screen all
  the same. TeamCamel now reads the card from the session's transcript and
  shows the session as awaiting input, with the question, until you answer
  it (or mark the session handled).


Version 2.9.1 - 2026-10-22
--------------------------

Fixed
- A session that once ran a program by its path (such as uv or rclone) was
  taken to own every later run of that program, including the connector
  programs Claude starts. Only scripts and other files of the session's own
  tie a program to it now, and nothing Claude Code or the Claude app's
  launcher starts is tied this way (those carry the session's mark). A
  script started again in the Claude app's Terminal panel still counts.


Version 2.9 - 2026-10-22
------------------------

Changed
- "Working in background" now also covers a program that lost the session's
  mark: one started again later, by you, by a scheduled job or by a script,
  such as an upload resumed after a pause. Such a program is tied to the
  session whose own commands named its script or file within the last 14
  days (the latest one to name it, when several did); what it starts belongs
  to the same session. It counts while it is busy, as before.
- --check and each computer's report say which programs were tied this way.


Version 2.8.1 - 2026-10-22
--------------------------

Fixed
- Work started by a long-lived session could be missed: the Claude app now
  and then gives such a session a new internal id, keeping the earlier ones,
  and a program started under an earlier id was not connected to the
  session. It now is.

New
- Each computer's report lists the programs its sessions started that are
  running, with their processor use and data moved, and --check shows them:
  to see why one counts as working or not.


Version 2.8 - 2026-10-22
------------------------

Changed
- "Working in background" now also covers a program a session started that
  copies or uploads: one moving data, on disk or over the network, hardly
  uses the processor, so 2.7 took it for an idle leftover (an overnight
  upload showed as completed). A program counts as working while it uses
  the processor, or moves more than half a megabyte a minute; a pause of up
  to two minutes does not end it. On a Mac disk and network are counted,
  on Linux everything a program reads and writes, on Windows as before.
  Uploading done by the Dropbox app itself, after a session copied files
  into a Dropbox folder, is Dropbox's work and is not counted.
- Hints when pointing at things now appear at once (after about a tenth of
  a second) instead of after the browser's own delay of a second or more.
  They are drawn by the page, in its colors.


Version 2.7 - 2026-10-21
------------------------

Changed
- Marking a session handled: an empty white square next to a session
  needing you, to tick, in place of the check mark. Pointing at it says
  "Mark if handled". Undoing (the arrow) is as before.

New
- Help messages when pointing at things: "Settings" on the gear, "Open in
  Claude" (or Codex) on a session's name, "Legend" on the colored words at
  the top right, and on the square, the ". . ." and the arrows.
- Settings, "Help": turns these messages off, for those who know the page.
  What a computer's name and a version number show when pointed at stays,
  being information rather than help.


Version 2.6.1 - 2026-10-21
--------------------------

Fixed
- Pointing at a session's name underlined its "Claude" or "Codex" label too
  (since labels came in, 1.7). Now only the name is underlined.


Version 2.6 - 2026-10-21
------------------------

Fixed
- A session whose turn ended with a question to you in plain words ("Take
  batch 6 as recommended?") showed as completed: Claude Code reports such a
  session idle. It now shows as awaits input, with the question. TeamCamel
  reads it where the Claude desktop app keeps it, the end-of-turn wrap-up
  and summary of each session, the way the app reads them; both are cleared
  when you reply. As with an interrupted session, one left unanswered for
  over 7 days, and no longer running, stops counting. Sessions started
  from a terminal have no such record and are unchanged.


Version 2.5 - 2026-10-21
------------------------

Changed
- A session whose folder was renamed or moved now simply carries on: its
  workspace shows under the folder's new name and TeamCamel follows the
  folder at its new place from then on, also after a restart. 2.4 only
  noted "folder moved or renamed". On a Mac, for folders TeamCamel has
  seen in their place (every session folder since 2.4).
- If the followed folder is gone and a folder of the original name exists
  again, the original name is used again.


Version 2.4 - 2026-10-21
------------------------

New
- "Handled": a session needing you has a small check mark. Click it once
  you have dealt with the session: it turns grey and stops counting as
  needing you (no notices, no red arrow) until it does something new. The
  arrow next to a handled session undoes it. The marks are kept in the
  shared folder, so every computer's page shows them.
- Archived sessions stay on the page in grey instead of leaving it: those
  archived in Claude or in Codex. They never count as needing you, also
  while still running. A setting under "Show" leaves them out instead.
- A session whose working folder was deleted turns grey and stops counting
  as needing you. A folder that was only moved or renamed is mentioned
  ("folder moved or renamed") and the session keeps its state. On a Mac
  TeamCamel tells the two apart by the folder's identity number, which it
  notes while the folder is there; elsewhere, and for a folder it never
  saw, a folder that is gone is only "folder not found", with no change.


Version 2.3 - 2026-10-21
------------------------

Changed
- One column per computer, side by side, in the order chosen in the
  settings (this computer first unless chosen otherwise). Before, three or
  more computers shared one column, "on others". When the columns do not
  fit the window, the row scrolls sideways.

New
- Arrows to sessions out of view. Small, softly blinking arrows show that
  working sessions (blue) or sessions needing you (red) are out of view:
  up and down in a narrow margin on the left, left and right at the top.
  When both point the same way they sit side by side (one above the other
  at the top). They change as you scroll, and clicking one brings the
  nearest such session into view.


Version 2.2 - 2026-10-20
------------------------

New
- Settings, "Refresh": how often TeamCamel reads the sessions and the page
  updates, from every 5 seconds to every 5 minutes; 15 seconds as before
  unless changed. Like every setting it applies to all your computers or
  only to the one you are at, as chosen at the top of the panel, and takes
  effect within a second. Other computers' statuses come through the shared
  folder, at most every 30 seconds (or as rarely as their own refresh).
- --check reports the refresh in force.

Changed
- The gear at the top left is 75% larger, easier to find and to hit.


Version 2.1 - 2026-10-19
------------------------

Changed
- Settings for "only this computer" now hold for every browser on it.
  Before, they were kept in one browser, so settings made in Safari did not
  show in Firefox. They are now kept in the shared TeamCamel folder, in a
  file for that computer; settings made in 2.0 are carried over the first
  time that browser opens the page.
- Version colors renamed, since what counts as a big version is a matter of
  opinion: latest (green), not the latest (grey), may be outdated (red).
- Settings, "Show": "Sessions:" (Claude, Codex) with the versions beneath
  it, then "OS(es):" (macOS, Windows, Linux).

Fixed
- "Try it" did not blink the tab title while the page was in view. It now
  blinks for a few seconds. A real notice blinks whenever the page is not
  the window in use, and stops when you come back to it.


Version 2.0 - 2026-10-19
------------------------

New
- Versions. Under each computer's name: the Claude Code and Codex versions
  it runs. Green: the newest. Grey: behind, within the same big version.
  Red: behind a big version. For Claude Code a big version is its first two
  numbers (2.1); Codex is still at 0.x and moves its second number almost
  weekly, so it counts as behind a big version at four releases (about a
  month). Hovering over a version shows the newest one. Codex counts at
  its newest on the computer: the codex command, the copy inside the Codex
  desktop app, or the version its sessions were run with.
- Settings, behind a gear at the top left. They apply to all your computers
  (kept in the shared TeamCamel folder) or only to the computer you are at
  (kept in its browser), as you choose:
  - which computers to show, and their order (the first one shown fills the
    left column);
  - Claude, Codex or both; computers by system (macOS, Windows, Linux);
  - the versions, and whether to look up the newest ones online once a day;
  - the colors of the page;
  - how to be told when a session starts needing you: a pop-up notice, a
    sound, a blinking tab title, in any combination.
- --check reports the Claude Code and Codex versions.

Privacy
- The daily look-up of the newest versions is off until it is turned on in
  the settings. It is made by the page, which asks the public npm registry
  for the newest Claude Code and Codex version numbers; nothing about you or
  your sessions is sent. While it is off, the newest version seen on your
  computers counts as newest.
- Only this computer's own page can save the shared settings: a request from
  any other web page is refused.

Tested
- macOS and Linux: automated checks for the version rules, the settings and
  their save (including requests from another web site, refused), and the
  notices; the page tried live in a browser. Pop-up notices depend on the
  browser's permission and were not tried on a real browser here.


Version 1.9 - 2026-10-18
------------------------

New
- Working in background. A session whose turn is over but whose work goes on
  now shows as "working in background (...)" in blue instead of completed,
  and turns to completed when that work ends. Counted:
  - commands and helper agents Claude sent to the background, from the
    records Claude keeps of when each starts and ends;
  - programs a session started that are still busy, such as a render, even
    after the session's window was closed. Every program a session starts
    carries a mark naming the session; one that sits idle (a helper service
    left running) is not counted.
  Awaits input and interrupted stay as they were, and the count of sessions
  needing you is unchanged.

Limits
- Work done inside another app's own window is not counted, for example the
  Blender app rendering at a session's request through its connector.
- On Windows only background commands and helper agents are counted.

Tested
- macOS and Linux (Ubuntu 26.04): automated checks with a background
  command, a helper agent, an idle leftover and a busy detached program, and
  a live run on each. Windows: by simulation only.

Tested

Version 1.7 - 2026-10-11
------------------------

New
- "Claude" label. When the page has both Claude and Codex sessions, every
  session carries a small label saying which it is. A page with sessions of
  one kind only stays without labels.
- Codex sessions open in Codex. Clicking the name of a Codex session opens
  that thread in the Codex desktop app, as clicking a Claude session opens it

  threads made in the Codex desktop app; a thread from the codex command in a
  terminal has no app to open it and stays plain text.


Version 1.6.1 - 2026-10-11
--------------------------

Changed
- Codex transcripts are read much faster, and a long Codex history can no
  longer hold up the start. Only the end of each transcript is read, and by
  pattern instead of as a whole. Each cycle spends at most two seconds on
  transcripts not read yet, newest first; until its turn comes a thread is
  listed as completed. Threads idle for more than eight days are listed as
  completed without their transcript being read.


Version 1.6 - 2026-10-11
------------------------

New
- Codex sessions next to Claude's. If OpenAI's Codex is installed (the
  desktop app or the codex command), its sessions appear on the same page, in
  the workspace of the folder they work in, each marked with a small "Codex"
  label. Nothing to set up, and nothing is changed in Codex: its thread list
  and transcripts are only read.
- How a Codex session's state is told. Codex publishes no live status, so it
  is worked out from the transcript: turn finished = completed; turn stopped
  by you = interrupted; a command asking for wider permissions with no result
  yet, or a question from Codex = awaits input; an open turn otherwise =
  working; an open turn while Codex is not running, or idle for a long time =
  interrupted.
- --check and the precheck report whether Codex was found.

Limits
- A Codex prompt of another kind than the two above may show as "working".
- TeamCamel still starts with Claude Code. A computer with only Codex has to
  start it by hand.
- Tested with the Codex desktop app on macOS (Codex 0.162). The codex command
  in a terminal, and Codex on Windows and Linux, were not tested.

Version 1.3 - 2026-10-10
------------------------

Changed
- The footer logo is 90% of its previous size.

New

- --uninstall: takes this copy out of Claude's start-up (the settings file is

Version 1.1 - 2026-10-10
------------------------

New
- Precheck, to run before installing:  sh precheck.sh  on macOS and Linux,
  precheck.bat  on Windows (double-click). It lists each thing TeamCamel needs
  as OK or MISSING, with what to do about each missing one, and changes nothing
  on the computer. It checks: Python 3.9 or newer; the TeamCamel files being
  complete and their folder writable; Claude Code being present; live session
  status being available; the Claude settings file being readable; the page's
  port being free. It also notes whether the `claude` command and the desktop
  app's session list were found, and whether the folder is in a synced
  location. The same check is available as  --precheck.
- --install-hook --port N, for a computer where another program uses port 2263.

Tested
- Linux, for real: Ubuntu 26.04 with Python 3.14. The automated checks (60 of
  63; the other three apply only to a Mac or to an installed copy) and a live
  run: precheck with Claude Code missing and with Python missing, one-time
  setup, the start hook, the page, self-restart, a Linux page showing a Mac's
  sessions and a Mac page showing the Linux sessions. Claude Code itself was
  not installed on that machine; stand-in files were written where and how
  Claude Code writes them, backed by real running processes.
- Windows: still by simulation only. precheck.bat has not been run on Windows.


Version 1.0 - 2026-10-10
------------------------

First numbered version.

The program
- One web page, http://127.0.0.1:2263/, listing the Claude Code sessions on
  this computer and on every other computer that shares the TeamCamel folder.
- Each session shows one of four states: awaits input, interrupted, working,
  completed. Awaits input and interrupted are red, working is blue.
- Order: the workspace with the most sessions needing you is on top. Inside a
  workspace: awaiting input, then interrupted, then working, then completed,
  most recent first. Everything needing you, everything working and the newest
  completed session are shown; the rest is under ". . .".
- The number after a computer's name, and at the front of the browser tab
  title, counts the sessions needing you.
- Left column: this computer. Right column: the other computer, or "on others"
  when there are several, with their workspaces mixed by the same order and
  each heading naming its computer.
- A computer that stops reporting is dimmed and no longer counted.
- Starts by itself with the first Claude session (a SessionStart hook added by
  --install-hook). Restarts itself when teamcamel.py changes; an open page
  reloads itself when web/index.html changes.
- Reads local files only. It contacts no online service and uses no tokens.
  The page is served to this computer only.

New in 1.0
- Windows and Linux support, next to macOS. A page on any of the three shows
  the sessions of all of them. Each computer reports its operating system;
  it is shown in the "on others" line and when hovering over a computer name.
- --check: reports what TeamCamel finds on a computer (counts and locations,
  never session names). The first thing to run when something looks wrong.
- --version, and "Ver. 1.0" at the end of the footer line.
- Another computer's report that is caught half-synced no longer makes that
  computer disappear from the page for a moment; the last good copy is kept.
- Fixed before it could show: a session started on day 1 to 9 of a month
  would not have been recognized as running.

Tested
- macOS: in daily use on two Macs.
- Linux and Windows: by 53 automated checks run on a Mac, with the operating
  system switched and made-up Claude files. Not yet run on a real Windows or
  Linux computer.

Not covered
- Cloud sessions and cloud routines (they run on Anthropic's servers), ordinary
  claude.ai chats, Cowork sessions, phones and tablets.

TeamCamel change log
====================

Newest version first.


Version 1.7 - 2026-10-11
------------------------

New
- "Claude" label. When the page has both Claude and Codex sessions, every
  session carries a small label saying which it is. A page with sessions of
  one kind only stays without labels.
- Codex sessions open in Codex. Clicking the name of a Codex session opens
  that thread in the Codex desktop app, as clicking a Claude session opens it
  in Claude. It works for sessions on the computer you are at, and for
  threads made in the Codex desktop app; a thread from the codex command in a
  terminal has no app to open it and stays plain text.


Version 1.6.1 - 2026-10-11
--------------------------

Changed
- Codex transcripts are read much faster, and a long Codex history can no
  longer hold up the start. Only the end of each transcript is read, and by
  pattern instead of as a whole. Each cycle spends at most two seconds on
  transcripts not read yet, newest first; until its turn comes a thread is
  listed as completed. Threads idle for more than eight days are listed as
  completed without their transcript being read.


Version 1.6 - 2026-10-11
------------------------

New
- Codex sessions next to Claude's. If OpenAI's Codex is installed (the
  desktop app or the codex command), its sessions appear on the same page, in
  the workspace of the folder they work in, each marked with a small "Codex"
  label. Nothing to set up, and nothing is changed in Codex: its thread list
  and transcripts are only read.
- How a Codex session's state is told. Codex publishes no live status, so it
  is worked out from the transcript: turn finished = completed; turn stopped
  by you = interrupted; a command asking for wider permissions with no result
  yet, or a question from Codex = awaits input; an open turn otherwise =
  working; an open turn while Codex is not running, or idle for a long time =
  interrupted.
- --check and the precheck report whether Codex was found.

Limits
- A Codex prompt of another kind than the two above may show as "working".
- TeamCamel still starts with Claude Code. A computer with only Codex has to
  start it by hand.
- Tested with the Codex desktop app on macOS (Codex 0.162). The codex command
  in a terminal, and Codex on Windows and Linux, were not tested.

Version 1.4 - 2026-10-10
------------------------

First version prepared for public release. The program works as in 1.3.

New
- README.md, with a screenshot made from made-up sessions.
- Public package:  python3 packaging/make_package.py --public  writes
  dist/TeamCamel-<version>.zip, the download (README.txt, LICENSE.txt,
  CHANGELOG.txt, both precheck scripts, the program and its page), and
  dist/github, the contents of the public repository. Both are checked for
  this computer's session names and private words before they are kept.


Version 1.3 - 2026-10-10
------------------------

Changed
- The footer logo is 90% of its previous size.

New
- --stop: stops the monitor. It starts again with the next Claude session.
- --uninstall: takes this copy out of Claude's start-up (the settings file is
  backed up first) and stops it. Hooks of other programs, and of another copy
  of TeamCamel elsewhere on the computer, are left alone.
- Friend / tester package:  python3 packaging/make_package.py --tester  writes
  dist/TeamCamel-<version>-tester.zip, holding a short README.txt, both
  precheck scripts, the program and its page. It is the running program
  unchanged except for the footer, which shows the logo and the version
  without the copyright line. The state folder (your own sessions) is never
  included, and the zip is checked after it is written.

Tested
- The tester zip was unpacked and run on a Mac, and on the Linux test machine
  by following the README: precheck, install, page, stop, uninstall.


Version 1.2 - 2026-10-10
------------------------

New
- The footer shows the TeamCamel logo in place of the word: the camel "M",

Version 1.1 - 2026-10-10
------------------------

New
- Precheck, to run before installing:  sh precheck.sh  on macOS and Linux,
  precheck.bat  on Windows (double-click). It lists each thing TeamCamel needs
  as OK or MISSING, with what to do about each missing one, and changes nothing
  on the computer. It checks: Python 3.9 or newer; the TeamCamel files being
  complete and their folder writable; Claude Code being present; live session
  status being available; the Claude settings file being readable; the page's
  port being free. It also notes whether the `claude` command and the desktop
  app's session list were found, and whether the folder is in a synced
  location. The same check is available as  --precheck.
- --install-hook --port N, for a computer where another program uses port 2263.

Tested
- Linux, for real: Ubuntu 26.04 with Python 3.14. The automated checks (60 of
  63; the other three apply only to a Mac or to an installed copy) and a live
  run: precheck with Claude Code missing and with Python missing, one-time
  setup, the start hook, the page, self-restart, a Linux page showing a Mac's
  sessions and a Mac page showing the Linux sessions. Claude Code itself was
  not installed on that machine; stand-in files were written where and how
  Claude Code writes them, backed by real running processes.
- Windows: still by simulation only. precheck.bat has not been run on Windows.


Version 1.0 - 2026-10-10
------------------------

First numbered version.

The program
- One web page, http://127.0.0.1:2263/, listing the Claude Code sessions on
  this computer and on every other computer that shares the TeamCamel folder.
- Each session shows one of four states: awaits input, interrupted, working,
  completed. Awaits input and interrupted are red, working is blue.
- Order: the workspace with the most sessions needing you is on top. Inside a
  workspace: awaiting input, then interrupted, then working, then completed,
  most recent first. Everything needing you, everything working and the newest
  completed session are shown; the rest is under ". . .".
- The number after a computer's name, and at the front of the browser tab
  title, counts the sessions needing you.
- Left column: this computer. Right column: the other computer, or "on others"
  when there are several, with their workspaces mixed by the same order and
  each heading naming its computer.
- A computer that stops reporting is dimmed and no longer counted.
- Starts by itself with the first Claude session (a SessionStart hook added by
  --install-hook). Restarts itself when teamcamel.py changes; an open page
  reloads itself when web/index.html changes.
- Reads local files only. It contacts no online service and uses no tokens.
  The page is served to this computer only.

New in 1.0
- Windows and Linux support, next to macOS. A page on any of the three shows
  the sessions of all of them. Each computer reports its operating system;
  it is shown in the "on others" line and when hovering over a computer name.
- --check: reports what TeamCamel finds on a computer (counts and locations,
  never session names). The first thing to run when something looks wrong.
- --version, and "Ver. 1.0" at the end of the footer line.
- Another computer's report that is caught half-synced no longer makes that
  computer disappear from the page for a moment; the last good copy is kept.
- Fixed before it could show: a session started on day 1 to 9 of a month
  would not have been recognized as running.

Tested
- macOS: in daily use on two Macs.
- Linux and Windows: by 53 automated checks run on a Mac, with the operating
  system switched and made-up Claude files. Not yet run on a real Windows or
  Linux computer.

Not covered
- Cloud sessions and cloud routines (they run on Anthropic's servers), ordinary
  claude.ai chats, Cowork sessions, phones and tablets.
